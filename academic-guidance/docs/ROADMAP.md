# خارطة الطريق — رشاد

بناءً على القرار: **كل المحاور معًا بمستوى أساسي في الإصدار الأول**، مع مستخدمين اثنين فقط (المرشد + الطالب)، ومصدر بيانات الدرجات هو استيراد Excel وPDF.

- [ ] `design-system.css` مستقل (لوحة ألوان رشاد).
- [ ] نظام الهوية: تسجيل دخول Supabase Auth، `profiles` بدور `counselor`/`student`/`super_admin`، تفعيل الحساب عبر إجراء إداري محروس.
- [ ] الترويسة الموحدة وقياس Safe Area (بوابتان: Counselor Workspace وStudent Portal).
- [ ] CI أساسي: `node --check` على كل ملف + `node --test` على اختبارات سلسلة قاعدة البيانات من مخطط فارغ.

## المرحلة 1 — MVP (كل المحاور بمستوى أساسي)

كل محور أدناه بمستوى CRUD أساسي وظيفي، دون تحليلات متقدمة أو أتمتة، ليعمل التطبيق كوحدة متكاملة من أول إصدار:

1. **إدارة القسم**: خطة قسم واحدة نشطة بالعام الدراسي + أهداف فرعية (نص + حالة). لا تقارير مرئية بعد.
2. **الأجندة التنفيذية**: قائمة أنشطة (عنوان، تاريخ، حالة، ربط اختياري بهدف)، عرض تقويمي بسيط أو قائمة مرتبة بالتاريخ.
3. **التذكيرات**: قائمة تذكيرات شخصية للمرشد (عنوان، تاريخ استحقاق، حالة، ربط اختياري بكيان)، مع تنبيه للمستحق اليوم/المتأخر في لوحة المرشد الرئيسية.
4. **سجل الطلبة**: استيراد أولي لقائمة الطلبة (Excel) أو إدخال يدوي فردي؛ حقول أساسية فقط (الاسم، الرقم الأكاديمي، الصف، الفصل).
5. **استيراد الدرجات وتحليلات أساسية**:
   - استيراد Excel (المسار الأساسي، الأدق) بقالب أعمدة ثابت.
   - استيراد PDF أساسي: استخراج نص + مطابقة نمط لقالب تقرير واحد شائع تحدده المدرسة أولًا (توسعة لقوالب أخرى لاحقًا).
   - شاشة مراجعة واعتماد الدفعة إلزامية قبل الحفظ.
   - تحليلات أساسية: معدل الطالب لكل فصل، ترتيب تقريبي داخل الصف، علم بصري بسيط لتراجع الدرجة عن الفصل السابق (بدون نمذجة إحصائية متقدمة).
6. **المتابعات والحالات الإرشادية**: فتح حالة لطالب (نوع + أولوية + حالة مفتوحة/مغلقة)، تسجيل جلسات متابعة نصية بتاريخ، إغلاق الحالة.
7. **خطط الدعم الفردية**: خطة دعم لطالب (هدف + تاريخ بدء + تاريخ مراجعة)، قائمة إجراءات بحالة إنجاز بسيطة (لم يبدأ/جارٍ/منجز).
8. **التوجيه المهني**: تسجيل جلسة توجيه مهني (تاريخ + ملاحظات + توصية) لكل طالب، دون تقييمات ميول آلية بعد.
9. **بوابة الطالب**: عرض درجات الطالب الأخيرة، عرض خطة الدعم إن أُتيحت له صراحة، نموذج طلب موعد بسيط.

**خارج نطاق MVP صراحة** (تُعتمد لاحقًا لا الآن): رسوم بيانية متقدمة، تنبيهات تراجع تلقائية عبر بريد/إشعار، تصدير تقارير PDF جاهزة، أدوار رئيس القسم/المعلم/ولي الأمر، تكامل مباشر (API) مع أي نظام مدرسي خارجي، تقييمات ميول مهنية آلية، دعم قوالب PDF متعددة.

## المرحلة 2 — تعميق التحليلات والتقارير

- رسوم بيانية لأداء الطالب عبر الفصول، ومقارنة على مستوى الصف/الشعبة.
- تنبيهات تراجع تلقائية (عتبة قابلة للتهيئة) تُنشئ تذكيرًا تلقائيًا للمرشد.
- تصدير تقارير PDF (تقرير حالة طالب، تقرير خطة قسم) من داخل التطبيق.
- توسعة محرك استيراد PDF ليدعم أكثر من قالب تقرير درجات.

## المرحلة 3 — توسعة الأدوار والتكامل

- دور رئيس القسم (تجميع تقارير عدة مرشدين).
- وصول محدود للمعلمين (رفع ملاحظة سلوكية أو أكاديمية تُنشئ اقتراح حالة، دون وصول لبقية الحالات).
- بوابة ولي أمر (قراءة فقط لخطة الدعم والدرجات بموافقة صريحة).
- تكامل API مباشر مع نظام مدرسي خارجي إن توفّر، بديلاً عن الاستيراد اليدوي.

## معيار الانتقال بين المراحل

لا تبدأ المرحلة التالية قبل أن تعمل كل محاور المرحلة الحالية فعليًا في الاستخدام اليومي للمرشد على بيانات حقيقية (لا بيانات تجريبية فقط)، تمامًا كما اعتمد CCE النشر التدريجي حسب Sprint فعلي مُختبر قبل الانتقال للتالي.
