# خارطة طريق CCE StableOS

تُراجع هذه الخارطة عند كل إصدار. الأولويات تعبّر عن ترتيب التنفيذ، ولا تمثل مواعيد تسليم ثابتة.

## المرحلة الحالية — تثبيت الأساس (P0)

- [x] هندسة موحدة لترويسات Desktop وTablet وMobile.
- [x] توحيد Safe Area على الجوال مع الصفحة الرئيسية.
- [x] فصل الحالة التشغيلية للخيل عن الحالة الصحية في الواجهة.
- [x] مزامنة إكمال المهام الصحية مع ملخص الخيل والتنبيهات.
- [x] إصلاح تحميل التنبيهات حسب الصلاحيات والبوابات.
- [x] إنشاء الوثائق الرسمية للمشروع.
- [ ] تطبيق ترحيل قاعدة البيانات v4.6.4 على بيئة Supabase والتحقق منه.
- [ ] اختبار قبول يدوي على iPhone/Android/Tablet/Desktop بأدوار مختلفة.

## المرحلة التالية — الاعتمادية والأمان (P0/P1)

- تجميع مخطط قاعدة البيانات الأساسي والترحيلات في سلسلة قابلة لإعادة البناء.
- إضافة CI لفحص JavaScript، الترحيلات، الروابط والأصول في كل Pull Request.
- مراجعة RLS وRPC لكل دور وتوثيق مصفوفة الصلاحيات.
- إضافة اختبارات تكامل لمسارات: الحجز، إكمال مهمة صحية، تسجيل دفعة، وجدول المدرب.
- إزالة الاعتماد التدريجي على الحقول الصحية القديمة بعد نقل جميع المستهلكين إلى الأحداث الموحدة.

## المرحلة الثالثة — الخدمات والتنبيهات (P1)

- خدمة تنبيهات خادمية موحدة تعتمد على أحداث النظام.
- Supabase Realtime للتحديثات الفورية داخل التطبيق.
- Web Push حقيقي عبر اشتراكات Push وخدمة خلفية، بدل الاعتماد على صفحة متصفح مفتوحة.
- مركز تفضيلات تنبيهات حسب المستخدم والدور ونوع الحدث.

## المرحلة الرابعة — المنصة المؤسسية (P1/P2)

- لوحات مؤشرات قابلة للتخصيص وتقارير تشغيلية ومالية متقدمة.
- دورة حياة كاملة للإيواء والعقود والفوترة.
- CRM موحد وتاريخ تواصل العميل.
- دعم فروع وإسطبلات متعددة عند اعتماد نموذج Multi-tenant.
- API وعقود تكامل موثقة للأنظمة الخارجية.

## بوابة الخروج لكل مرحلة

لا تُعد المرحلة مكتملة قبل نجاح الاختبارات، تحديث الوثائق وCHANGELOG، وجود خطة رجوع لقاعدة البيانات، ومراجعة الأمان والصلاحيات.
