# رؤية المشروع — رشاد (منصة الإرشاد الأكاديمي والتوجيه المهني)

## هوية المنتج

**رشاد** منصة عربية أولًا لقسم الإرشاد الطلابي والتوجيه المهني في المدرسة. المنتج ليس أرشيفًا رقميًا فحسب، بل نظام عمل يومي للمرشد الطلابي يوحّد خطة القسم، الأجندة التنفيذية، التذكيرات، ملفات الطلبة، تحليلات الدرجات، سجل المتابعات والحالات، وخطط الدعم الفردية في مصدر واحد موثوق.

## الرؤية

أن يصبح رشاد الأداة اليومية التي يعمل منها المرشد الطلابي فعليًا بدل الاعتماد على ملفات Excel وWord متفرقة، مع تجربة واضحة على الجوال، وسجل موثوق لكل طالب، وحماية صارمة لبيانات الحالات الإرشادية الحساسة.

## المستخدمون الأساسيون (الإصدار الأول)

- **المرشد الطلابي**: المستخدم الأساسي — يخطط، يستورد الدرجات، يتابع الحالات، يبني خطط الدعم.
- **الطالب**: وصول محدود للقراءة على بياناته الخاصة فقط (درجاته، خطة الدعم إن وُجدت) وطلب موعد مع المرشد.

مستخدمون مؤجلون لمراحل لاحقة (غير مشمولين في MVP): رئيس القسم كدور منفصل عن المرشد، المعلمون، أولياء الأمور، الإدارة العليا كمستهلك تقارير فقط. البنية (الأدوار والصلاحيات) تُصمَّم من اليوم الأول بحيث تستوعب هذه الأدوار لاحقًا دون إعادة هيكلة، لكنها لا تُبنى الآن.

## مجالات النظام

| المجال | الوصف المختصر |
|---|---|
| خطة القسم | الأهداف السنوية للقسم ومؤشراتها وحالتها |
| الأجندة التنفيذية | الأنشطة والفعاليات المجدولة المرتبطة بخطة القسم |
| التذكيرات | مهام ومواعيد فردية للمرشد، مرتبطة اختياريًا بطالب أو نشاط أو خطة دعم |
| سجل الطلبة | البيانات الأساسية لكل طالب: الصف، الفصل، ولي الأمر، التواصل |
| الدرجات والتحليلات | استيراد الدرجات من Excel وPDF، ولوحة تحليل أداء لكل طالب/مادة/فصل |
| المتابعات والحالات الإرشادية | سجل حالات (أكاديمية / سلوكية / اجتماعية) وجلسات المتابعة لكل حالة |
| خطط الدعم الفردية | خطة تدخل لكل طالب: أهداف، إجراءات، متابعة تقدم، مراجعة دورية |
| التوجيه المهني | جلسات وتوصيات التوجيه الجامعي والمهني للطالب |
| بوابة الطالب | عرض الدرجات وخطة الدعم الخاصة بالطالب، وطلب موعد |

## مبادئ المنتج

1. بيانات الحالات الإرشادية بيانات حساسة درجة أولى؛ الوصول إليها مقيّد ومسجَّل دائمًا (Audit)، ولا يُعرض أي منها في شاشة عامة أو تقرير غير محمي.
2. استيراد الدرجات لا يكتب بصمت: كل دفعة استيراد (PDF أو Excel) تُعرض للمراجعة والاعتماد قبل الحفظ النهائي، وكل دفعة قابلة للتراجع الكامل.
3. العربية وRTL والجوال حالات أساسية وليست تحسينات لاحقة — المرشد يعمل غالبًا من الجوال بين الحصص.
4. الأمان والصلاحيات جزء من التصميم من اليوم الأول (RLS + RPC)، وليس طبقة تُضاف قبل الإطلاق.
5. لا خلط بين البيانات الأكاديمية (الدرجات) والبيانات الإرشادية الحساسة (الحالات) في نفس الجدول أو نفس مستوى الصلاحية.
6. كل تعديل مهم قابل للتتبع والاختبار والترحيل بأمان، والوثائق وقاعدة البيانات والكود تُحدَّث معًا.

## معيار النجاح

ينجح المنتج عندما يستطيع المرشد الطلابي إدارة يومه الكامل (الخطة، الأجندة، المتابعات) من داخل التطبيق دون العودة إلى ملفات خارجية، ويستطيع استيراد كشف درجات فصل دراسي كامل ومراجعته خلال دقائق بدل ساعات، ويثق بأن بيانات حالات الطلبة الحساسة محمية ولا يراها إلا من يملك صلاحية صريحة.
